# 秀米界面操作与易错点

本文件记录已使用过的操作方式；界面可能变化，以当前可见控件为准，不复用旧坐标、元素编号或浏览器会话。

## BrowserSkill 会话与定位

- 浏览器操作通过 BrowserSkill（`bsk`）执行。`bsk session start --no-focus --browser <id> --json` 建立会话并保留返回的 session_id，之后所有命令带 `--session <id>`；任务结束（无论成败）执行 `bsk session stop <id>`。命令细节以 `bsk --help`、各子命令 `--help` 及已安装的 browser-skill 技能文档为准，不猜测参数。
- 读取页面用 `bsk observe` / `bsk snapshot`，返回带 `@eN` 引用的语义树；操作用 `bsk click @eN`、`bsk fill @eN --value "…"`、`bsk press` 等。导航或 DOM 变化会使引用失效，先重新观察再操作。
- 秀米画布是 contenteditable 富文本编辑器，`fill` 支持编辑器根节点。文字级修改优先点入段落、选中目标文字后经浮动菜单设置格式；先做一处小范围修改并核实效果，再继续同类操作。
- 视觉自检（SKILL.md 自检第 4 条）用 `bsk screenshot`（视口或全页）；截图用于核对效果，不替代语义读取。
- 页面忙碌时 `bsk evaluate` 会偶发返回空对象 `{}`：等待 2～3 秒重试，或改用 `bsk observe` 验证；连续失败先停下等页面空闲，不要盲目换方法。
- 会话可能中途失效（命令报 `session not registered or already stopped`）：重新 `bsk session start`，用 `bsk tab list` 找回已打开的图文标签页。`tab borrow` 借用用户标签页需要人工确认，无人值守时会超时失败；直接在新会话的标签里重新导航到同一 URL 即可（同一浏览器配置保持登录态）。
- 页面里同名控件常有隐藏副本（可见一组加隐藏模板若干），泛匹配选择器会命中隐藏元素而报 `no visible geometry`。稳妥做法：evaluate 给目标可见元素赋唯一 `id`，`bsk click --selector "#id"` 后再移除该 id；对“保存”“删除”等关键按钮一律如此，不要依赖裸类名选择器。
- 浮动工具栏（复制/删除等）是悬停或选中组件后短暂出现的：用 `bsk hover` 真实悬停唤出后立即点击；点击报元素不可见说明工具栏已淡出，重新选中组件、重新标记再点。合成的 `MouseEvent` 不触发秀米的 Angular 逻辑，组件级点击（封面块、图库图）必须用 `bsk click --selector` 走可信事件。

## 秀米编辑态与数据同步（关键机制）

- 秀米是 Angular 应用，**只有组件处于“编辑态”（单元格获得焦点，class 含 `tn-on-editing`）时的修改才会写入数据模型**；对未激活组件直接改 DOM 并派发事件，改动只在渲染层，一旦重新渲染或保存刷新就会回退丢失。
- 可靠的文字替换管线：`bsk fill @ref --value "x"`（激活编辑态）→ `evaluate` 中选中全部内容后 `document.execCommand("insertHTML", false, 完整标记)`（走编辑管道，进模型）。标记里的强调一律用行内 `<strong><span style="color: …">`，整段包在单个 `<p>` 内，避免块级断裂造成段内断行。
- 每完成一处修改，用“点击其他组件再看回来”或保存刷新验证是否真正持久化；发现回退立即用上述管线重做，不要在渲染层反复修补。
- 单元格级样式（写在 cell `style` 上的字号、对齐、行高等）直接改 DOM 会被 `ng-style` 重渲染覆盖。可靠做法是在数据模型上改：`angular.element(单元格).scope().cell.style.<键> = 新值`，再 `scope.$root.$apply()`，之后读取计算样式确认。模板残留的相对字号（如 `87.5%`）就用此法改为与正文一致的明确 px 值。
- 保存优先用快捷键 Cmd/Ctrl+S（`bsk press "Meta+S"`）。用选择器点击“保存”按钮有误点相邻按钮的风险（曾误触“放弃修改并离开”确认框）；确需点击时按 marker-id 方式锁定可见按钮。

## 保存验证与服务器真相

- 保存是否成功以服务器数据为准：同源请求 `GET /api/shows/<图文id>`（带 credentials）返回标题、封面 `cover` 和数据版本指针 `show_data_name`（路径末段是毫秒时间戳）。保存后该时间戳必须变化；不变即未保存成功。
- 编辑器顶部工具栏自左向右为：打开、预览、保存（悬停提示 ⌘+S）、导出、更多。收尾顺序按 SKILL.md「保存与同步」执行：保存完成 → 导出 → 同步到公众号 → 等待导出进度条走完且无报错弹窗；出现"出错啦…网络错误"类对话框时按「编辑器异常状态诊断」处理后重试。
- 正文数据 JSON（`show_data_url` 指向的文件，gzip 压缩）用 shell `curl --compressed` 下载后核对文字、封面地址与内联样式是否已写入；JSON 内 HTML 是转义形式，检查 `font-size:` 等片段时注意转义引号。浏览器页内 `fetch` 拉 `sd.xiumius.cn` 的文件会跨域失败，页内只取 API 元数据，文件内容交给 shell curl。
- `GET /api/shows/<id>/histories` 列出历史版本备份（`sd.xiumius.cn/history/...` 下的 gzip JSON），可用于核对“丢失前”的内容状态；下载后 `gunzip` 解开查看。

## 模板表工作流：查表、转存、删除与维护

- **查表**：《推送模板表》（xlsx + md 速查版）在排版工作区。速查版按内容类型给出首选模板的秀米 ID；用编辑链接 `https://xiumi.us/studio/v5#/paper/for/<id>/cube/0` 在已登录浏览器打开，核对标题与内容后再作为模板使用。
- **列表页定位**：图文列表按 14 条/页懒加载，不自动无限加载；旧文用搜索定位——搜索框 `input[placeholder*="输入标题或描述"]` 填词后**必须点击搜索图标**（`a.glyphicon-search`）才触发，仅回车不生效。同名拷贝卡片必须按秀米 ID 区分：卡片容器 `.show-item`，编辑链接 `a[href$="/paper/for/<id>"]`。
- **卡片操作按钮**是带 `title` 的 `span.action-btn-small`（`copy`=另存给其他用户、`tag`=设置标签、`delete`=删除），另有 `span.glyphicon-edit`（编辑标题）；悬停浮现但元素常驻 DOM，标记唯一 id 后 `bsk click --selector` 点击。
- **转存**：点「另存给其他用户」→ 弹窗页签「另存给个人 / 另存给团队 / 另存二维码 / 另存记录」→「另存给个人」联系人表首行「自己｜另存给自己」勾选 →「确定」（未选择时该按钮 disabled）。转存副本保留全部组件样式，原稿不动；副本数据 `authorAppendix.actions.copyFromShowId` 记录来源 ID，可核对转存关系。转存后立即改标题并打「模板」标签。
- **删除与额度**：点卡片删除按钮**没有二次确认**，直接删除并提示“已删除至回收站”——务必按 ID 定位后再点。额度（「已保存图文」计数，`GET /api/shows/count?show_type=paper&version`）删除后立即减少；回收站（路由 `#/studio/recycle`）不占额度，为腾额度无需彻底删除。
- **清理重复的验证**（删除前必做）：下载两篇正文 JSON（方法见上节），比较 `htmlForPreview` 去标签文本与 HTML 的相似度、图片 `src` 差集，并核对 `release_at`/`saved_at`。文本相似度 1.0（或一方图片为另一方严格子集且文本相同）才算重复；相似度低或双方均已发布的变体不算重复，保留。多份同名取保存最新且方向明确的那份保留，修版方向（谁缺图、谁更新）核对后再删。
- **重新扫描维护模板表**：列表 `GET /api/shows/by/untag?show_type=paper&team_id&limit=100&page=0&sort_by=created`（页内 fetch 带 credentials），单篇元数据 `GET /api/shows/<id>`；正文 JSON 用 shell `curl --compressed` 下载，从 `$appendix.htmlForPreview` 提取全文文本、字号分布、主题色、图片数、署名等特征；自由画布格式无该字段，按 `cubes` 递归兜底提取。上次扫描与生成脚本在排版工作区 `tpl-survey/scripts/`（`extract.py` 提特征、`annotate.py` 生成 xlsx 并把 xlsx 与 md 速查版同步复制到本 skill 的 `references/`），路径如变动以当次为准；逐篇的内容归类与模板角色需人工判断，脚本只产特征底稿，md 速查版为手工评注文件。

## 编辑器异常状态诊断

- 秀米编辑器是 hash 路由（`/studio/v5#/paper/for/<id>/cube/0`）。**不要给这类 URL 追加查询参数**（如 `?fresh=1`）——会破坏路由并静默打开一篇空白新图文（hash 变成 `/paper/for/new/...`）。
- 看到标题“(无标题)”、正文空白时，先核对 `location.hash` 是否已被带到 `new`——可能只是在另一篇空白文档上，不是目标图文丢了数据。
- 弹出“检测到…上次没有保存到服务器，是否恢复？”（本地草稿恢复）：本地草稿通常比服务器新，意外中断后一般选“确定”恢复；选“取消”则从服务器加载。两者都安全，选完核对完整性（标题、各节文字、封面）。
- 弹出“出错啦…网络错误”对话框：数据请求瞬时失败，点确定关闭后重新加载，等待渲染完成（大图文需 15 秒以上）再核对内容。
- 疑似“文章变空/被覆盖”时，先用“保存验证与服务器真相”的方法查服务器版本指针和 JSON 内容，确认服务器真相后再决定恢复手段；不要凭页面假象立即重做或重写。

## 组件复用（图文收藏）

- 并列条目（项目介绍、规则清单等）优先用左侧“图文收藏”面板的现成组件：点开“图文收藏”，逐个标签页浏览，下拉查看组件缩略图，点选即插入到当前选中组件之后。
- 复制已有组件：合成鼠标事件点选组件外层包装（避开文字区，否则进入文字编辑态）→ 浮动工具栏“复制”→ 组件进入左侧剪贴板（可同时存多个切片）→ 选中锚点组件后点击剪贴板切片预览，即插入到锚点之后。
- 剪贴板有多个切片时按预览文字与纵向位置区分（如卡片切片与正文切片文字不同）。
- **插入锚点必须取“章节层级”的组件包装**（`opera-tn-ra-comp` 路径恰好到 `col1:数字` 结尾），从文字单元向上找最近的包装会把新组件嵌进内部布局，造成逐级缩进嵌套；插入后核对路径层级与视觉宽度是否与相邻组件一致。
- 删除组件：选中后点击浮动工具栏的红色按钮（`btn-danger`，删除）；键盘 Delete/Backspace 在文字编辑态只会删文字。
- 组件插入后改文字同样走“编辑态 + insertHTML”管线；缩略图上的编号（01/02…）若为装饰图形会随位置自动递增，无需逐个修改。
- **每个组件操作（复制、粘贴、删除）完成后立即双重验证再做下一个**：截图看视觉效果，并核对组件路径层级、视觉宽度与相邻组件一致。曾出现粘贴出“标题在卡片外”的错位卡片、删除错相邻组件等事故，均因连续操作没有逐步核实。
- 删除会使其余组件的路径整体位移：每次操作前重新查询组件路径和 `querySelectorAll` 顺序，不沿用上一次的序号。
- 点击剪贴板切片前确认左栏当前停在“剪贴板”面板：模板库缩略图可能与剪贴板切片占据相近屏幕区域，仅凭横向坐标过滤会误点模板、把整块模板插到文末。粘贴前核对切片结构完整（标题在卡片内、无错位）；切片异常时不要修补，回到源组件重新复制。

## 文字与组件

- 点击段落进入编辑，选择要修改的文字，通过当前界面的组件菜单或浮动菜单调整字号、加粗、文字颜色、对齐等。字号调整须先选中文字，再使用组件菜单中的字号选项（以实际界面为准）。
- 不需要的段落或组件：选中后点击浮动菜单的删除按钮。删除前确认选中的是目标段落，而不是整个外层布局。
- 新段落：选择前一个段落 → “后插空行” → 点击新空行 → 输入文字。
- 需要复用模板样式：选中合适组件，复制到目标位置，再替换文字或图片。保留与之配套的边框、装饰。
- 首次点击有时只选中外层组件，尚未进入文字编辑。设置格式前检查真实选区与焦点；工具栏状态可能未及时更新，不要盲目切换加粗而把已有加粗取消。

## 字号、加粗和主题色

1. 精确选择目标文字，检查浮动工具栏。
2. 先按 SKILL.md 选择模板方案或无模板推荐方案，再设置对应字号。优先使用字号下拉选项；若输入数值，确认替换整个原值，避免把“16”追加在“15”之后形成错误字号。
3. 对关键词应用加粗，同时在颜色菜单选择“文字颜色”，选择本篇确认的主题色；无模板时推荐清华紫 RGB (102, 8, 116)。
4. 如颜色面板显示详细色值和“应用颜色”，需要点击应用才算完成；不要误用“文字底色”或“全文替换”。
5. 取消选区后观察实际样式，确认颜色、加粗及字号都正确，再继续下一处。
6. 从模板复用的组件（尤其署名区、图注）用 `getComputedStyle` 读取渲染后的实际字号核对，不依赖工具栏显示：模板可能残留相对字号（如 `font-size: 87.5%`），渲染结果与正文不一致。确认残留后按“秀米编辑态与数据同步”一节在数据模型中改为与正文一致的明确值。

有模板时从页面主题色或模板现有强调样式确认本篇颜色；不要将历史文章的具体紫色色值套用于所有文章。

## 上传和替换图片

- 左侧“我的图库” → “上传图片（无水印）”。定位到该入口后用 `bsk upload @eN --file <本地路径> --session <id>` 上传当次素材；默认模式点击入口并拦截文件选择器，不依赖系统文件对话框，支持重复 `--file` 传多张。仅在明确的拖放区且默认模式未激活文件输入时，尝试 `--mode drop` 一次。远程模式不支持上传，本流程按本地模式执行。
- `bsk upload` 可能因扩展“允许访问文件 URL”权限被拒（错误 `Not allowed`）：备选方案是在页面内用 evaluate 构造——base64 → `fetch(data:…)` 取 blob → `new File` → `DataTransfer` 赋给 `input[type=file]` 并派发 `change` 事件，同样能触发图库上传；上传后用图片字节数或 MD5 核对图库中确实出现了当次文件。
- 页面里有多个 `input[type=file]`，多数是隐藏的拖放区模板，往隐藏 input 注入文件不会有任何反应。从**可见的“上传图片(无水印)”按钮**文字向上找最近的可 `input[type=file]` 再注入；大文件 base64 分块（每块约 250KB，`window.__b64` 累加）可绕过 evaluate 参数长度限制。
- 插入图片后按图片类型在右侧面板定宽度（百分比下拉＋步进按钮，步进档位可能是 10%，取最接近目标值的档位）：正文内容图与二维码 **50%～80%**（按信息密度取值）；头图、海报、整版装饰图可 **90%～100%**；小物件展示图可 **15%～40%**。内容图不要保持默认的 100% 全宽。
- 推荐保留已有图片布局：复制图片及其装饰边框，点击其中的原图片，再点击左侧已上传的目标图片，实现替换。
- 直接插图：在目标位置建立空段落，再点击图库中的图片。
- 每次替换后检查是否修改了正确图片、边框是否保留、比例与裁切是否正常，图注是否属于该图。

## 图文设置浮层与封面

- 设置浮层（标题、摘要、作者、封面块）随页面滚动：封面块 `div.image.tn-lighting-box` 不在视口时先用 `bsk scroll-to` 滚回来。浮层滚出视口或未打开时点击图库图片，会退化成“往正文插图”的普通模式——这是封面图误入正文的最常见原因。
- 设封面流程：真实点击封面块（`bsk click --selector "div.image.tn-lighting-box"`，合成事件无效）进入封面选择——单击封面会提示"点击图库换图"，在图库中点击已上传的目标图片即设为封面（图片恰为 2.35:1 时不弹裁剪框）→ 核对封面块 `background-image` 或模型 `deskCtrl.showData.cover` 已指向新图 → Cmd+S 保存。
- **裁剪封面**：鼠标悬浮在方形封面区上，左上角会出现按钮（≡ 样式；旁边另有其他图标，功能未逐一核实，操作时避开），点击后选择"裁剪封面"，弹出裁剪窗口，提供 **2.35:1 与 1:1 两种比例**；1:1 即从大图中截取一个小的方形区域。窗口内交互：鼠标放在图片上为"移动"，上下左右拖拽调整裁剪位置；鼠标移到四角的白色圆圈上变"缩放"，按住拖拽可放大缩小裁剪选取框。完成后点右下角"**应用**"保存封面设置，点"**放弃**"则撤销此次的全部操作。Agent 执行时：拖拽用 `bsk drag`（支持相对偏移），角点缩放先 `bsk hover` 再 drag，"应用/放弃"用 marker-id 锁定后点击。
- **封面安全区（选图与生图共同要求）**：封面会被裁成 2.35:1 横幅与 1:1 方图两种样式；重点内容（标题文字、核心人物）必须能完整落进 1:1 方形裁切区（画面中央，左右留白充足），否则朋友圈/会话卡片等方图场景会切掉关键信息。生成式封面先逐字校验文字无乱码再上传，构图同样按此安全区执行。
- 浮层未开时误点图库图片插入正文：选中误插组件，marker-id 锁定工具栏红色 `btn-danger` 删除，确认删净后重做封面流程。
- 作者栏保持留空（SKILL.md 通用规则）；摘要默认沿用原稿导语，不额外扩写。

## 生图渠道（封面/配图生成，可选）

- 需要生成封面或配图时，默认渠道是维护者本机的 MOSS 生图链路（moss-t2i 技能：经 CPA 网关调用 MOSS-SFT INT8 模型）。其 token 与配置在维护者机器的 `~/.config/moss-t2i/config`（权限 600），**不随本 skill 分发**——其他人安装本 skill 不会获得 MOSS 调用权，moss-t2i 未配置时不得尝试调用。
- **自定义生图渠道**：使用者可用自己的渠道替换默认值，在任务中提供——API 端点（OpenAI images 兼容或自定义格式）、key 的存放位置（环境变量名或本机配置文件路径；不要让用户把 key 直接贴进对话，更不要写入任何被提交的文件）、模型名与生图参数（尺寸/比例、数量等）。按用户提供的参数调用，key 只在运行时从其存放位置读取。
- 生图结果上传前逐字校验图中文字无乱码；构图按封面安全区规则执行（重点内容落在 1:1 方形区内）。上传后按「上传和替换图片」一节定宽。
- 渠道不可用或调用失败时，如实说明并请用户提供图片或改用自定义渠道，不擅自换用其他未授权的生图服务。

## 间距处理

- 标题前后、图片前后各空一行；普通段落之间可空一行。章节之间保持约 2～3 行的视觉间距，将已有留白计入，不机械叠加。
- 图片图注与下一节标题之间留空行，不能紧贴。
- 如果两节之间特别空，检查空段落、空组件以及上下边距或内边距是否叠加。逐个删除多余空组件，观察结果；不要为缩小间距删去正文或整节布局。
- 字号、行高与组件间距都会影响视觉距离，不能只数空白组件个数。对比相邻章节的实际间距。

## 输入与验证注意事项

- 通过 BrowserSkill 的 observe/snapshot 做语义定位，必要时辅以截图定位；每次操作后读取状态确认。
- 若中文输入或粘贴出现丢字，立即核对并纠正。替换整个富文本字段可能丢失格式，不把整字段替换作为局部着重的捷径。
- 原稿文件可用本地文档工具读取。例如 DOCX 的正文可由标准文档库或其 XML 提取；若存在表格、文本框或其他结构，须完整读取，不能只取普通段落就声称全文已核对。
- 页面正文应从当前可见界面或工具允许的页面读取能力获取，按段落与原稿比较。标题、图注、署名单独核对，避免误算进正文或遗漏。
- 点击保存后观察保存状态；同步后查看明确成功反馈。菜单关闭本身不证明操作已执行。

## 防止操作未生效却报告完成

- 编辑前记录目标图文的标题、可见标识或地址及当前标签页。多个同名标签页或模板副本并存时，核实当前目标，不凭标题相同认定为同一篇。
- 页面重绘、滚动、打开菜单或修改内容后重新获取界面状态，不复用旧元素编号或坐标。先做一处小范围修改，取消选区后核实效果，再继续同类操作。
- 样式核对结合可见效果和选中文本后的组件字号、加粗及颜色值。基础格式默认值不能代表每段实际字号；富文本容器的出现也不能证明强调色与加粗同时生效。
- 图片逐张核对实际内容，确认占位图已替换；搜索或逐段检查“点击输入文字”等残留。
- 保存验证与视觉验证分开进行：预览核对整篇视觉效果；保存以明确状态及同一图文重新打开后的结果为依据。若操作连续两次无可验证效果，停止重复同一方法，重新检查焦点、选区和目标；仍无法确定则如实报告具体未完成项。
